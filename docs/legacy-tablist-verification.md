# 1.7 玩家列表与固定布局

`vanilla-names-v2` 保留原版真实玩家名单，补充名字颜色，并单独限制发给 1.7 的登录包 Tab 容量。没有假 UUID、假玩家行、页眉页脚或排序数字。服务器实际人数上限和新版客户端不受这个容量设置影响。

## 为什么上一版仍有满屏空格

服务器 `max-players=2000` 经 ViaBackwards 5.11.0 的 1.16.2 → 1.16.1 转换后变为 255。1.7 客户端按这个固定容量画背景格：255 格分成 13 列，每列名字宽度只有 23 个 GUI 像素。实际在线人数只控制是否在格子里画名字，删除假玩家不能改变这些背景格。

已核对本机 CheatBreakerRemastered-1.7 的 `TabEditorModule.render()`、1.7.10 Forge 的 `GuiIngameForge.renderPlayerList()` 和实际安装的 ViaBackwards 字节码。客户端按每列至多 20 行计算列数，再按 `min(150, 300 / columns)` 计算列宽。

`v2` 在原版 Join Game 包发出时，将其中 maxPlayers 限制为默认 20：单列、150 个 GUI 像素宽。1.21.11 登录包是不可变 record，代码用原始组件重建该 record，仅替换 maxPlayers，保留实体编号、世界信息、视距、模拟距离和登录标志。对包做一次性替换，不修改服务器容量，也不重发登录包。

## 配置与限制

配置位于 `plugins/Alley/providers/tab-list.yml`：

```yaml
tab-list:
  legacy:
    display-slots: 20
```

旧配置没有该项时自动补充默认值，无需手动操作。旧的 `legacy.enabled` 和 `legacy.order-prefix` 不再生效。

- 默认 20 格：一列，最多画出 20 个真实玩家名字。
- 可设 40 格：两列，最多画出 40 个真实玩家名字，两列仍各有 150 GUI 像素宽。
- 支持范围 1～40；超出范围会限制到边界，避免再次产生窄列。若真实服务器容量更小，则保留较小值。
- 实际玩家数量超过显示容量时，原版客户端不会画出超出部分的名字，服务器仍允许这些玩家进入。
- 人数不足时，固定容量内仍有原版背景格。原版 1.7 没有单独动态修改 Tab 容量的包，纯服务端不能让背景格严格随人数增减。不会重发 Join Game 强行刷新，那会重建客户端世界。
- 修改显示容量后需要重启并重新连接；颜色变化无需重连。

## 名单和颜色

名字优先使用观察者 scoreboard team 的生效颜色，没有队伍时使用已加载档案的名字颜色。每 10 tick 在主线程检查一次，变化时才发 UPDATE_DISPLAY_NAME。原版 ADD/名字重置会使颜色缓存失效，隐藏后重新显示可以重新着色。只更新真实 UUID 的显示名，不自行 ADD 玩家；ViaRewind 会忽略不存在的 UUID，因此颜色更新不会恢复已经从名单移除的隐藏玩家。

显示名字段最多 16 个原始字符，颜色占 2 个。15～16 字符用户名在显示名字段中保留完整名字；原版客户端仍可按完整名字查找 team 并应用 prefix/suffix。不截断真实名字。

Tab 路径不修改 scoreboard/team，保留 `teams-v4` 的 ViaRewind 侧栏修复。新版页眉页脚仍使用原有设置。旧版布局和颜色不受全局/个人自定义 Tab 开关影响。

## 部署与实机检查

完全停服，替换自行构建的 `target/Alley-3.1.1.jar` 后启动，让 1.7 客户端重新连接。不要热重载。

启动日志应出现 `[LegacyTablist] renderer=vanilla-names-v2 displaySlots=20`，同时保留 `[LegacySidebar] renderer=teams-v4`。1.7 登录时应有 `[LegacyTablist] Applied login display limit=20 for 玩家名`，用于确认登录包改写实际执行。

1. 单人登录时 Tab 为一列，名字完整；剩余空背景属于固定 20 格，不能再出现之前的 13 列满屏窄格。
2. 两名玩家在同一可见场景登录、退出、重连，检查每个真实名字仅出现一次，没有标题、页脚、假名或数字。
3. 检查大厅、对战、队伍切换、观战和返回大厅后的名字颜色；颜色不变时不应周期闪烁。
4. 检查隐藏/显示、不同对局隔离，颜色更新不恢复已隐藏的玩家。
5. 检查 14～16 字符用户名、侧栏持续可见、新版客户端布局和服务器实际容量未变。
6. 如需显示 21～40 人，设置 display-slots 为 40，重启重连后检查两列宽布局。

本地检查见 `scripts/test-legacy-sidebar.ps1`，包含名字/连接缓存、不可变登录 record 的完整复制、255 格问题复现、20/40 格宽度边界，以及 Join Game 早于 PlayerJoinEvent 时的 Netty 协议识别。它们不代替真实 1.7 客户端与 Via 链的联调。
