# MinemenClub 击退分支与验证

此分支参考本机 `ClubSpigot-main` 的 `EntityLiving#a`、`EntityHuman#attack` 和 `EntityArrow` 实现。该参考项目是民间复刻，不能据此保证与 Minemen 正式服完全相同。

## 启用

插件启动后会补充 `plugins/Alley/knockback/MinemenClub.yml`，已有文件不会覆盖。

使用 `/kit setprofile <kit名称> MinemenClub`，下一次进入该 kit 的对局、FFA 或 Bot 对局时生效。名称不区分大小写，也可带 `.yml`。无需打开 `oldSwordBlockKB`；选择此配置后自动使用旧版伤害、剑格挡、无攻击冷却、无横扫和旧版弹射物兼容。旧版食物和附魔等其他独立开关保持原有设置。

MinemenClub 始终使用配置中的 `hit_delay`，不受 kit 的 `oldHitDelay` 开关影响。它表示完整 NMS 受伤窗口；默认 20 tick，上半段以格挡前的完整伤害判定：相同或更低伤害拒绝，更高伤害先补差，再计算格挡和护甲。补差命中不重启窗口。

default、1_8 的原有选择规则与击退公式保留。

## 修改配置与重载诊断

编辑服务器实际运行目录下的 `plugins/Alley/knockback/MinemenClub.yml`。项目 `src/main/resources` 是发布时的默认资源；服务器已有文件不会被它覆盖。

`/alley reload` 只打开菜单，本身没有重载文件。原有版本只有 **Knockback Profiles** 或 **Reload All** 会读取击退文件，**Config Files** 遗漏了这一目录。本次修复后 Config Files 也会重载击退配置；Reload All 对该目录只重载一次。只调击退数值时仍建议使用 Knockback Profiles，避免重载无关服务。

重载后控制台会输出击退目录和 MinemenClub 实际加载的参数。对局内使用管理员命令 `/alley debug kb`，或 `/alley debug kb <在线玩家名>`，查看玩家实际的 branch、assigned、resolved、受伤窗口与内存参数。它不会触发攻击或改写击退数值；不是每次命中的发包追踪。应当看到 `branch=MINEMENCLUB`，且 assigned/resolved 对应所选配置。大厅内未应用配置时显示 none 属正常情况。

诊断也显示 `friction.horizontal`、配置中的 `gravity`、服务器最终重力属性和 `Knockback gravity` 状态。未受击和击退上升阶段应保留原重力，状态为 idle 或 waiting；仅有效击退后的下落阶段为 active。有其他插件/药水修正时，最终属性可能与配置基准值不同。旧客户端显示下落速度补偿模式及当前会话的 packets 计数。

MinemenClub 每次命中都通过 manager 查询当前配置，没有将 settings 永久缓存在玩家身上。同一配置的数值重载后用于后续命中；更改 kit 的配置选择或配置文件的 branch 则应重新进入对局，不能用数值重载假定现有玩家已经切换分支。

### 为什么调 horizontal 后体感变化可能很小

MinemenClub 使用顶层标量 `horizontal`、`vertical` 和 `sprint-multiplier`，不使用 legacy 的 `horizontal.ground/air/sprint_extra`。新增独立 friction 前，horizontal 还参与计算旧速度继承除数；现在显式配置 friction 后，两者分开调整。horizontal 仍不是最终击退的直接倍数：

```text
基础水平冲量 ≈ 0.24 + 0.16 × horizontal - 距离衰减
旧水平速度继承 = 旧速度 / friction.horizontal
成功近战额外水平冲量 = 0.5 × sprint-multiplier（攻击者朝向）
成功近战最终 Y = min(vertical, 启用的 vertical-limit-value) + 0.1
```

上述水平基础项在 Java 实现中还经过 float 转换。水平额外冲量与基础冲量的方向可能不同，不能在所有场景下直接相加。

以目标静止、无抗性、正向命中、距离不超过衰减阈值、sprint-multiplier=1 为例：horizontal 从 0.8755 改到 0.5755，最终水平速度约从 0.88008 变为 0.83208，只下降约 5.5%。旧实现中更小的 horizontal 还会保留更多旧水平速度；新增独立 friction 后，显式除数不再受 horizontal 修改影响。vertical 从 0.25635 改到 0.26635，则近战最终 Y 只是从 0.35635 变为 0.36635。此例固定 sprint-multiplier=1，不代表当前资源文件中的用户设置。

本地检查时，服务器只有 NodebuffLGC 选择 MinemenClub，BoxingLGC/SumoLGC 仍选择 1_8。该配置下 legacy 的静止、正向、无附魔疾跑命中水平约 0.81、Y=0.36（未触发 W-tap 额外冲量）；与修改后的 MinemenClub 0.83208/0.36635 本来就接近。这些是指定条件下的速度向量，不是最终击退格数，不能单靠体感判断分支是否生效。

### 重载验收

1. 进入明确选择 MinemenClub 的对局，查询 `/alley debug kb`，核对分支和当前内存参数。
2. 保存击退配置，选择 Knockback Profiles 重载，核对控制台和诊断中的新值；再次命中使用新配置。
3. 分别通过 Config Files、Reload All 重复参数核对，确认每次操作只有一组击退重载日志。
4. 确认 legacy/default 对局仍显示各自分支；修改 MinemenClub 不改变它们的击退公式。

旧 jar 可先通过 Knockback Profiles 验证配置。新增诊断及 Config Files 修复需要之后明确要求构建、部署的新 jar；本次没有替换运行服文件。

## 独立 friction 与 gravity

```yaml
friction:
  horizontal: 1.8755
gravity: 0.08
```

`friction.horizontal` 是继承原 X/Z 的除数，必须是有限正数：2 保留一半、1 全部保留、4 保留四分之一，小于 1 会放大原水平速度。它同时保留与受击方向垂直的分量，沿用 Club 完整 X/Z 继承，而不是 legacy 的投影算法。

近战、箭、雪球、鸡蛋、鱼竿、珍珠兼容路径和 Bot 使用同一个基础计算，因此统一读取受击者配置中的 friction；攻击者的 sprint-multiplier 仍只控制额外近战冲量。基础 Y 原本就直接替换为 vertical，并没有 Y/2 的继承；不额外增加纵向摩擦。抗性拒绝基础击退和受伤窗口内补差时仍跳过基础阶段，保留原速度后加允许的额外冲量；不会为了套 friction 而重新施加基础击退。近战/Punch 额外冲量、攻击者运动恢复和 Bot 交付也不再除一次 friction。

已有 MMC 配置缺少此键时，加载/重载会将原除数 `2 - (1 - horizontal)` 写入 friction.horizontal；例如 horizontal=0.5755 则补入 1.5755。之后独立调整，修改 horizontal 不会自动改变显式 friction。零、负数和非有限 friction 在内存中回退到原除数，日志和 debug 显示实际采用的值。

gravity **只控制有效击退后的下落加速度**：普通跳跃、未受击的自然下落、击退上升及顶点保持原有重力。使用 Paper `Attribute.GRAVITY`；已从当前 SparklyPaper 1.21.11 字节码确认默认 0.08、合法区间 [-1, 1]。在获准的下落阶段，较小的正值下降更慢，较大正值下降更快，0 为无重力加速度；0 不会清空已有 Y 速度，也不会解除原有阻力。负值会向上加速，检测到重新上升后结束本次效果。超范围或非有限值回退到 0.08。

仅最终未取消、且确实改变速度的 MMC 击退会授权一次下落；被 hit delay 拒绝的攻击、被取消的速度事件、完全未改变速度的抗性/补差路径不启动效果。每次有效击退先清理上次效果，真人等待 `ping + 100ms` 并消费旧样本，再根据核心接受的新位移判断下落；Bot 使用服务器速度判断。观察到负 Y 后才通过插件独有的 transient ADD_NUMBER 修正施加配置基准值，原属性 baseValue 和其他来源的 modifiers 保留。

分配配置、重载、复活只登记或重置状态，不立即施加自定义重力；后续有效击退读取新配置。落地、重新上升、传送、换世界、死亡/观察者及特殊移动环境结束本次授权，不能延续到下一次普通跳跃或自然下落。切换分支、离场、退出或插件关闭时也清理状态，只移除 Alley 自己的修正，不把其他插件的重力重置为 0.08；transient 修正不会存入玩家数据。假死流程不改。

**原生重力属性需要 1.20.5+ 客户端。** 现代客户端和原生 Bot 也仅在上述下落阶段修改属性。1.7.10、1.8 等已确认版本的旧客户端只在该阶段创建垂直增量补偿会话。服务器保留目标重力属性，在 ServerTickEndEvent 读取核心已接受的最新移动 `ServerPlayer#getKnownMovement()`，仅将重力与原版的差额追加到客户端当前 Y 速度。开始下落补偿时不再额外等待一次发包宽限。未知协议仍跳过并提示，避免误判原生支持。

差额为 `deltaY = (0.08 - 实际gravity属性) × float(0.98)`：原版 `(Y-0.08)×阻力` 加上该差额，等于目标 `(Y-gravity)×阻力`。X/Z 冲量恒为 0，不重新指定或重放完整速度，不再次套用 friction.horizontal，不从旧样本积分 Y。这消除了旧补偿将延迟位移重建为整包速度、重新施加旧横向运动的路径。

传输使用只发给本人的无破坏 EXPLOSION 包，以利用旧客户端已有的相对速度追加语义：中心 `(0,20000,0)`、强度 0、方块数 0、空声音，粒子在远端不可见。它不创建服务器爆炸，不造成伤害或破坏方块，不广播给其他观察者。该方式与本机 ViaBackwards 5.11.0 的 `EntityPacketRewriter1_21_2` 用远端包追加玩家运动的方式一致；已核对中间版本转换保留冲量，1.20.3→1.20.2 丢弃粒子/声音字段时仍保留三轴 float 冲量，ViaRewind 的 1.8/1.7 路径沿用该格式。

同一已接受移动样本只消费一次，每个服务器 tick 最多一包；没有新移动时不追加、不追赶补算漏掉的 tick，也不按 ping 成倍补发。使用 NMS 的 Vec3 身份区分样本，并排除 ClientTickEnd 无移动时写入的共享 ZERO；不从可能陈旧的 Bukkit getVelocity 重复积分，也不依赖会在小位移时限流的 PlayerMoveEvent。实际 gravity=0.08 不发补偿包。补偿仍受服务器与客户端 tick 差异、网络延迟影响，不能宣称与原生属性完全一致；宽限期间极短的落地再起跳无法仅凭最后一份位移精确区分。

补偿包保留 ProtocolLib 的 EXPLOSION 过滤和取消能力，不调用 Player#setVelocity，不触发 PlayerVelocityEvent/击退重算，不设置 hurtMarked，也不写回服务端 deltaMovement。因此不会把补偿速度带入后续 KB 继承或实体跟踪的速度同步。包元数据携带会话及代次，不依赖 ThreadLocal，支持过滤延后执行；每人最多一个未完成的补偿包，超过 1 秒未完成则停用该会话。在离场、传送、新冲量或超时后，HIGHEST 过滤会取消仍在流程中的旧补偿包，MONITOR 只采集发送结果。其他来源向本人发送的速度/爆炸包会暂停补偿 `ping + 100ms`，等待新冲量及其后续移动返回。这个等待期间旧客户端仍使用原版重力，连击频繁或高 ping 时自定义重力覆盖时间会缩短。

落地、死亡、观察者、飞行、载具、睡眠、鞘翅、激流、水/岩浆、攀爬、漂浮/缓降药效和检测到的特殊介质会结束本次击退重力及补偿会话。传送/换世界、真实复活、配置重载和换 kit 同样清理；离场、退出及关闭插件移除会话/监听器。增量按旧协议 float 精度传输，不再使用绝对速度包的 ±3.9 或 1/8000 量化。反射、依赖链接或发包失败会对该会话停用补偿、移除自身属性修正并只记录一次错误；后续有效击退可创建新会话。

验收重点：在移动中改变 friction=1/2/4，分别核对 X/Z 继承及固定 Y；覆盖近战、弹射物、补差和 Bot，确认只除一次。现代客户端、Bot、1.8 和 1.7.10 分别比较 gravity=0.04/0.08/0.12：普通跳跃与从平台走出的自然下落保持一致；受击初速度和上升阶段保持一致，仅受击后的下降不同。落地后的下一次跳跃/自然下落不得继续受影响；被取消或 hit delay 拒绝的命中不得启动效果，连续有效命中应重新等待下落。核对重载、真实复活、假死、/leave、传送、换分支和关闭插件后的恢复。用 `/alley debug kb` 确认 idle → waiting → active → idle；1.7/1.8 只在 active 且有新移动时增长 packets，0.08 无补偿会话，现代玩家与 Bot 不进入补偿会话。增加延迟后检查横向是否无伤续推/回弹、连续命中与顶点抖动、是否无爆炸声/粒子；双方向核对 1.7↔1.8 和同版本对局的玩家显隐，并核对原服移动检查/反作弊是否接受，不能只凭属性数值认定已经实测成功。

## 数值及机制

- 完整继承原 X/Z：除以 `friction.horizontal`；旧配置缺省时迁移为 `2 - (1 - horizontal)`，不做沿受击方向的投影。
- 基础水平冲量：`float(0.4 * (1 - 0.4 * (1 - horizontal))) - R`，使用攻击者到受击者的水平方向。
- 距离是双方位置的三维距离。距离不超过 `start-range-reduction` 时 `R=0`；超过后 `R=min(range-factor * (distance - max-range-reduction), min-range)`。保留源码在阈值处的跳变。
- 基础 Y 固定为 `vertical`；可选上限先作用于基础 Y。没有 legacy 的离地高度截断。
- 每次成功玩家近战都额外叠加攻击者朝向的 `0.5 * sprint-multiplier` 水平速度和 `0.1` Y，不要求疾跑，不按击退附魔等级叠加。朝向计算保留旧版 float 与三角函数查表。
- 基础击退抗性按概率判断。受伤窗口内的伤害补差跳过基础击退；成功近战的额外冲量仍然保留，既不重新施加摩擦，也不重新限制 Y。
- 普通近战在同一次原生攻击的速度事件中交付最终向量；拦截原生基础和额外击退，恢复攻击者被现代攻击流程削减的 X/Z 和疾跑状态。不主动减速或中断疾跑，不附加 legacy 的 W-tap 奖励。
- 箭、雪球、鸡蛋、鱼竿和兼容路径中的珍珠使用同一基础公式。箭的 Punch 额外沿箭飞行水平方向增加每级 `0.6` 和一次 `0.1` Y；不套用 legacy 独立箭参数。1.21.11 的原生 Punch 使用 `PUSH` 事件，单独拦截匹配该箭的冲量。
- 剑格挡不采用 Alley legacy 原有的 80% 随机成功率。进入近战攻击流程后，无论是否被 hit delay 拒绝，都在本次攻击返回时清理攻击者实际使用物品状态与插件格挡标记；自动点击不会立即把格挡重新抬起。
- 成功近战击退清理受击者的 fallDistance。原有假死、复活、观察者、结果和回大厅逻辑不作改写。
- Bot 使用相同计算；原生玩家攻击发包后还原服务器速度时，由 Bot 适配器应用一次最终速度。已经作用到实体的弹射物击退只通知反馈层，避免下一 tick 再次施加速度。
- 重置受伤状态、换 kit、传送、退出、配置重载和关闭插件时清理待交付状态。

Club 原默认值：horizontal `0.9055`，vertical `0.25635`，sprint-multiplier `1`，range-factor `0.025`，max-range-reduction `1.2`，start-range-reduction `3`，min-range `0.12`，vertical-limit `true`，vertical-limit-value `4`。当前资源文件保留用户的 horizontal `0.9255`、vertical `0.25335`、sprint-multiplier `0.625`、gravity `0.067`；friction.horizontal 为 `2.0755`。

## 本轮对齐的 1–4 项

1. 伤害窗口保存格挡前的完整伤害。例如原始 7 点格挡后扣 4，记录仍是 7；松开格挡后再吃同伤害攻击会被拒绝。原始 10.5 的后续重击先得到差额 3.5，再格挡为 2.25（护甲前）。被取消的事件不提交窗口，Boxing/Sumo 的有效零伤害命中仍保存原始伤害。
2. 玩家攻击包、Bot 和自动点击进入同一攻击入口，完成后解除攻击者格挡，包括被受伤间隔拒绝的近战。距离校验失败、没有执行近战时不强制解除格挡。
3. 历史位置按 Club 的最小 30ms 间隔记录，保留原实现实际的 41 条上限。以攻击者 ping + 92ms 回溯目标并线性插值；记录不足时使用当前位置。任一方是服务器 Bot 时使用当前位置。历史只影响距离接受，击退方向和衰减仍使用当前位置。
4. 视线由攻击者眼睛指向目标当前眼高的 1、2/3、1/3 三处，任一条畅通即可。有视线时脚到脚的三维距离平方上限是 36，无视线时是 12.75，两者都包含边界。视线使用当前位置，距离使用回溯位置。

客户端实体选取距离在此分支固定为原版 3.0（旧配置的 2.9 也按 3.0 应用）；服务器 6 格接受上限不等于客户端可以 6 格选取。仅 MinemenClub 攻击者的明确玩家目标 ATTACK 包由插件接管，原包取消后调用普通 Player#attack 一次，保留 PrePlayerAttack 和 Bukkit 伤害事件。右键交互和其他分支不接管。本分支不再通过挥空射线扩展额外命中。传送、换世界、重生、换 kit、离场和重载时清理历史和伤害窗口。

本轮未改弹射物探测伤害、独立护甲和食物开关、异步发包线程、异步实体跟踪、instant interaction 或喷药参数。

## 实服验证

建议分别使用 1.7.10 和现代客户端重复以下步骤，并先确认当前 kit 已选 MinemenClub。

| 场景 | 检查点 |
| --- | --- |
| 静止、无附魔、非疾跑近战 | 2 格内沿正前方命中静止目标，horizontal=0.9255、sprint-multiplier=0.72 时总水平约 0.74808、Y 约 0.35635；这是速度向量，不是最终移动格数 |
| 疾跑与非疾跑、击退 I 与 II | 成功近战的固定额外冲量一致；攻击者不被服务器减速或强制停疾跑 |
