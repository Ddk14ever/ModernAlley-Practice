# 致死结算与旧客户端重力回归

本轮仅修改插件源码，未构建、部署或执行 Java 回归程序。运行服配置保持原样。

## 已确认的根因与修复

- 运行服使用 authlib 7.0.61，构建依赖为 authlib 6。`GameProfile` 的 `getName/getId/getProperties` 已变为 record 访问器，旧动画抛 `NoSuchMethodError`；原 `catch Exception` 捕获不到这个 `LinkageError`。致命一刀、Sumo 进水与 Boxing 达标都可能在视觉反馈处中断，未继续完成假死/结算。
- `GameProfileAccess` 兼容两代访问器和皮肤属性的可变/不可变构造。尸体保持独立随机 UUID。死亡动画自身及 `Match.playDeathFeedback` 均隔离依赖链接错误，动画失败不得阻断游戏状态推进；不改变原有无死亡屏幕、无真实复活的流程。
- 原 gravity 补偿按延迟返回的位移重发整条 X/Y/Z，可能无伤重新施加旧横向速度。现改为仅向本人追加 `deltaY=(0.08-gravity)*float(0.98)`，X/Z 增量恒 0，不写服务端实体速度。兼容范围包含 1.7 和 1.8，仍只在有效击退后的下降阶段授权。

## 实服验证

分别覆盖 1.7↔1.8、1.8↔1.8、现代客户端↔1.8，核对双方视角和控制台。

| 场景 | 预期 |
| --- | --- |
| 生存伤害 Kit，目标剩半颗心，再给致命一刀 | 正常进入原有假死/结果流程，无 `GameProfile` 错误、无卡在消失状态；死亡者不见死亡屏幕/泥土加载 |
| 同场景，观察击杀者视角 | 保留最终受伤音效和假尸体倒下，尸体随后移除；真人 UUID/皮肤不被尸体清理影响 |
| Sumo 被击入水，包括刚跨入水的一步 | 立即走淘汰/结算，不循环受伤音效；下一局正常 |
| Boxing 达到配置命中目标（通常 100） | 达标时正常结束，不继续累计到 120；下一局命中数与状态正常 |
| MMC，单次受击后停止攻击、侧向移动 | 下降补偿不无伤续推旧 X/Z，不出现横向二段回弹；对手保持可见 |
| MMC 连续对刀、不同延迟 | 新有效击退重置下降授权；被受伤间隔拒绝的攻击不新施加击退；无爆炸声/粒子 |
| gravity=0.04/0.08/0.12 | 普通跳跃、自然下落、击退上升不随参数改变；只比较受击后下降。0.08 无补偿包 |
| 落地后再跳、假死、传送、重载、换 Kit、/leave | 原下降效果结束，无旧包重放到新状态 |

`/alley debug kb <玩家>` 可核对协议、实际分支、gravity 模式及 idle/waiting/active。旧客户端 active 会话的 packets 只在接受到新移动时增长，不补发漏掉的 tick。高延迟下阶段切换仍是服务器观测的近似。

兼容签名已按本机 SparklyPaper 1.21.11、authlib 6/7、ViaBackwards 5.11.0、ViaRewind 4.1.3 和 ProtocolLib 核对。可在明确授权构建后执行 `GameProfileAccessRegression` 与 `MinemenClubRegression`；源码检查和数值核对不能替代上表的客户端验证。
