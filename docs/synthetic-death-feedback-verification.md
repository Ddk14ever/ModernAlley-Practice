# 假死音效与死亡动画验证

此修改不调用真实玩家的死亡、维度重载或重生接口，不改变现有假死、回血、背包清理、对局结算和回合复活流程。

致命伤害被取消时，先在死亡位置播放一次玩家受伤音效，再执行原有假死流程。只向有效击杀者发送一个独立实体 ID、独立 UUID 的假玩家，复制受害者当时的位置、朝向、皮肤和装备，发送血量为零的元数据与原版死亡状态。假人不加入世界、不参与战斗；20 tick 后清理，插件关闭时也清理。死亡者与其他观战者都不接收这个假人的数据包。

1.7 的特殊处理依据 ViaVersion 5.11.0 / ViaBackwards 5.11.0 / ViaRewind 4.1.3 的实际接口：在该连接的 Netty 线程内，将假人的独立皮肤资料临时登记到 ViaRewind 的生成缓存，生成后清除。没有向 1.7 发送假人的 Tab 添加/删除包，也不复用真人 UUID，避免覆盖 ViaRewind 的真人实体映射。现代客户端使用未列入 Tab 的独立资料。

同一玩家同一 tick 的多个死亡处理入口合并为一次反馈。近战、投射物和水晶优先使用当前致命伤害来源识别击杀者；环境淘汰使用现有战斗归属。主动 `/leave` 不触发死亡假人或受伤音效，Bot 自身保持原生死亡表现。

按项目约定，本次没有构建或运行需要编译的检查；数据包反射签名已与本机 1.21.11 服务端及上述跨版本 jar 静态核对。以下客户端效果需要实机验证。

使用击杀者 A、受害者 B 和观战者 C，分别测试 1.7.10 和 1.21.11，并交换 A/B 的客户端版本：

1. Bot 战斗中执行 `/leave`、`/botleave`：聊天区出现一次带玩家名字颜色的 `disconnected.`；Bot 立即移除，能够开始下一局。已结算后退出不重复播报。
2. A 近战击杀 B：最后一击有受伤音效；A 看见 B 的皮肤与装备变红、按原版动作倒下，约一秒后消失。B 不看见死亡假人、死亡界面或泥土加载界面；C 不看见新增假人。
3. 换用箭、水晶及环境淘汰重复测试；第三人打出最后一击时，动画应只给实际最后一击的玩家，不能给较早攻击者。
4. 在队伍淘汰、StickFight、带复活倒计时的套件与快速复活模式测试，确认原有回血、复活位置、复活时间与对局结算没有变化。
5. 连续击杀、迅速 Play Again、击杀者换世界或退出连接：不能遗留假人、误删真人、影响下一局玩家显示。
6. 按住 Tab 观察 1.7：不能新增重复名、空名字或占位格；动画结束后真人名字、颜色、装备和侧边栏仍正常。
7. 自杀、无玩家归属的死亡与 Bot 击杀真人：有受伤音效，不向无关玩家生成死亡假人。真人击杀 Bot 的原生动画不应叠加第二具假人。

若假人包生成失败，只记录首次异常，原有假死与复活继续执行；可在日志中查找 `Could not show client-only death animation` 获取具体反射/协议错误。
